03 — Method

How the case was built

  1. Clean.Lower-cased text, stripped anonymized #URL_hash#/#EMAIL_hash# tokens, HTML entities and punctuation, and combined title, company profile, description, requirements and benefits into one field per posting.
  2. Explore.Checked class imbalance, posting length, and how structured flags (logo, remote, screening questions) differ between genuine and fraudulent listings.
  3. Vectorize.Converted cleaned text into TF-IDF features (single words, top 4,000 by frequency) so models can weigh which terms are most distinctive of fraud.
  4. Train & benchmark.Fit five classifiers — Logistic Regression, Random Forest, Naive Bayes, Linear SVM and Gradient Boosting — on a 75/25 train/test split, class-weighted where supported.
  5. Score.Compared models on accuracy, precision, recall and F1, since accuracy alone is misleading on a dataset where only 4.8% of postings are fraudulent.
04 — The Verdict

Benchmarking five classifiers

On imbalanced fraud data, precision and recall matter more than raw accuracy — a model that never flags fraud still scores 95%+ accuracy while catching nothing.
